## 从消融得到的训练选择

除注明外，学生均为 Qwen3.5-4B-text，全参 SFT。TH3K 主线用 262144 token 上限，完整轨迹一行、显式坏回复 loss=0、超长丢弃。历史 c312 用 16 卡、单卡 microbatch 1、梯度累积 4、全局 batch 64、长度分组、恒定学习率 1e-5。下表按问题归并同一系列的 checkpoint，逐臂的采样、job 与结果见[结果长表](sft_results.md)和[TH3K 逐题消融](th3k_ablation_by_task.md)。

|问题|改动与评测|结果与后续动作|
|---|---|---|

本地 TB2.1 的最新记录到 11 月 14 日。统一题面、测试、可写层和资源限制后，教师 dsv41-v2 留有 150/178 的完整对账。4B、9B、randfix 等学生在快照中仍有补测，TB4 也缺完整结果。这里的“本地 TB2.1”指原集群的 `tb_local`；当前 SSH 机器另有 Ceph 训练工程复现。两者分别见[本地评测账本](local_tb21_runs.md)和[迁移训练实测](server_training_checks.md)。

本机 8×H100 的 304 步随机调度配方已完成前 10 步校验，28 层卸载、有效 batch 64，累计 81,642,520 个 token。65K 配对短测中，20 层较 24 层吞吐提高 6.2%，但在最长八条轨迹上显存不足。复现完整 10 步采用已验收的 28 层配置。[H100 卸载实验](h100_offload.md)

## 从错误进入下一轮实验

1. **任务漏项。** mirror c312 的 105 条失败中，26 条人工主因归为漏需求或未经运行便交卷。先固定权重和题集，仅在确认轮要求模型给每条需求对应的命令输出。复查 PARTIAL 样本是否真正补齐缺项，再以相同行为筛出训练集之外的真实教师示例做单变量 SFT。
2. **终端状态丢失。** 13 条主因归为终端被占用、进入续行或提前退出。用独立任务生成“识别提示符状态 → 恢复 → 验证进程或文件”的短轨迹。按同一分类比较每百条的终端失效、成功恢复和最终通过数。
3. **长任务消耗。** 41 次 TTL 是失败结局，其中既有困难任务，也有终端与外部依赖问题。按轨迹区分停滞位置，采集能先交付最小产物、读取短反馈并换方案的正例。看首次有效产物时间、TTL 和 pass@all 是否共同改善。
4. 同一实验固定模型、harness、reward、资源与题集，登记数据版本、监督 token、warmup、调度方式、checkpoint、job ID 和原始路径。报告通过/总数、逐题得失与失败构成。要判断约 5 点的变化，可扩大到每题 6 次采样，按题汇总不确定性。用独立开发任务筛查新数据，TB2.1 留作复测。

逐轨迹依据见[105 个失败样本](c312_failure_cases.md)、[教师与学生行为对照](trajectory_failures.md)和[TH3K 近似题核查](th3k_overlap.md)。
